# 任务排队执行，故障后显式重新派发

AgentDock 默认全局同时执行 4 个外部任务，并允许用户调整上限；超过上限的已接收任务进入队列，同一项目内由 AgentDock 管理的写任务串行执行。达到容量上限属于等待执行，而不是任务失败。

第一版直接在指定项目目录执行，不为每项任务自动创建 Git worktree。同项目串行约束只覆盖 AgentDock 管理的写任务，Codex 主代理仍需协调与其他执行者的文件修改范围。

连接断开后自动重连并恢复已有任务的展示；任务失败或后台异常退出后，由 Codex 明确决定是否重新派发，AgentDock 不自动重新执行已经开始的任务。界面重连与重新执行任务是不同操作，这一选择用可见的中断状态换取对重复文件修改等副作用的控制。

后台异常退出后，原先运行的任务标记为中断，尚未开始的排队任务转为暂停，由 Codex 明确决定后续执行。仅恢复界面连接不解除这些暂停状态。

任务接收时固定其角色提示词和超时配置；之后的角色配置修改只用于新接收的任务，已在排队或执行的任务保持原配置。这样可以按接收时的约定解释任务行为，代价是调整配置不能直接修正既有排队任务。

这些规则是 AgentDock 的目标行为。既有服务的重复请求复用能力可以作为协议设计参考；排队机制和新的界面交互需要单独实现与验证。
