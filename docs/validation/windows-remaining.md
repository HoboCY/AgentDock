## 修复与短测

数字输入框的模板内 `PART_TextBox` 原来没有 UIA 名称。现在为并发数和五个角色的超时输入框设置名称；真实键盘探针发现六个名称完整、空名称输入框为零。Windows 讲述人“语音回顾”截图确认逐项读出名称及数值；因讲述人的 UIA 文本读取受完整性级别限制，该项是截图人工核验，不把自动读取空文本冒充通过。证据：`guest-evidence/keyboard-state.json`、`narrator-recap.png`。

业务管道连接等待由 700 ms 改为 3,000 ms；后台启动探测仍为 700 ms。写入请求后不重试或重放。MCP 区分连接超时、响应超时、调用方取消和传输中断，并提示不确定结果时不要重复派发。受控“管道被占用 1.1 秒”用例在旧代码失败、新代码通过；取消和写入后断管不重放亦有回归。**这证明了短连接预算的缺陷，不证明此前那一次偶发 MCP Unavailable 就由此造成。** 原诊断日志同步写盘可能影响阶段耗时，不能单靠那份耗时归因后台锁竞争。

150% 实测发现原主窗口越过工作区，悬浮窗右侧超出屏幕。Windows 修正根据实际屏幕缩放换算像素位置、约束窗口尺寸，通知窗口在布局完成后定位。Windows 专属尺寸与定位分支不扩展到其他平台。初步修正于 150%/200% 实际 DPI 144/192 下通过主要控件和悬浮窗边界检查；最终候选继续复验小分辨率及通知位置。

本地完整回归加实际沙箱补测：**119 项不同的 Windows 测试通过，19 项仅适用 macOS 的测试跳过**。证据分别在 `regression/`、`tests/transport-before.trx`、`tests/transport-after.trx`、`tests/transport-classification.trx`。后续改动仅为 Windows 通知定位时机和平台边界，验证采用候选包真实 UI 检查。

## 12 小时验收口径

`scripts/Probe-WindowsSoak.ps1` 锁定 Host/Desktop 的 PID、启动时间及程序路径，每 15 秒采集窗口 WM_NULL 心跳、只读 status、CPU、工作集、私有内存、句柄、线程、物理内存及执行进程数，分小时汇总。对 IPC、窗口超时、进程退出或替换、样本缺口、时钟异常、写盘失败及 AgentDock 崩溃/挂起事件保留失败证据；错误 PID、会话不匹配不能通过。连接令牌只在内存中用于请求，不输出到证据。

完整时长、足够样本、无异常及结束时未完成任务和产品执行进程均归零才允许采样器给出 completed。私有内存持续增长另外标记人工复核，采样器成功不等于已证明无内存泄漏。宿主与 VM 用临时执行状态阻止自动睡眠，结束后释放，不改永久电源计划；手动睡眠、注销、关机或关 VM 会中断验收。

正式计时前 60 秒有效短测已通过：12 个运行样本和 1 个收尾样本，13/13 IPC 成功、窗口心跳无超时、无事件异常、写盘错误为零；错误 PID 负例按预期失败。首次短测暴露 PowerShell 将 File.Replace 的 `$null` 绑定为空字符串，修正为 NullString 后复测成功。短测证据为 `guest-evidence/soak-short-result.json` 及 VM `soak-short2/`，不能当作 12 小时结果。

长测与十轮合成五角色任务结合，后四角色并发四，保留真实 Codex 插件连接、调用结果、用量、文件权限和重复请求身份断言，同时以 650 ms 的只读任务查询增加管道压力。任务运行次数有上限，不持续无界调用模型。最终结论还需核对十轮结果、停止/重连、长测内存趋势与结束后的进程清理。

## 首轮负载失败与接收循环修复

`.2` 的十轮真实五角色任务均完成，Host PID 未变，实际观察到四并发。但 650 ms 辅助查询有 855 次成功采样及 9 次失败；长测状态查询也有一次约 2,015 ms 的连接失败，窗口心跳没有超时。额外阶段计时观察到一次约 8,838 ms 的 list 返回，其中约 8,415 ms 位于读取等待阶段。整体压力验收判失败，不能用任务最终成功覆盖通信失败。

`Program.ServeAsync` 直接调用异步处理器时，已缓冲请求可在第一个不完整 await 前同步进入业务锁或持久化写入，从而阻塞继续接收连接。提取的接收循环现在单独调度处理器，仍先创建下一监听实例，保留 Unix socket 生命周期行为。受控回归用一个同步阻塞的处理器加三个真实管道客户端：旧行为第三个客户端两秒内连接超时；修复后通过。它证明该接收循环缺陷，仍不把实机所有长延迟均归因于这一机制。

修复后 Core/Host 为 31 通过、3 平台跳过，结合未变化执行引擎的已有通过结果，当前为 **120 个不同 Windows 测试通过、19 个 macOS 平台跳过**。证据：`tests/accept-before.trx`、`tests/host-accept-fixed.trx`。候选 `.3` 构建完成；新一轮使用独立的 `artifacts/validation/windows-remaining-r2-20261016/`，避免覆盖首次失败记录。
